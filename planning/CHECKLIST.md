# Preparation and execution checklist

## Completed preparation
- [x] Read previous task README, queue scripts, analysis artifacts and report structure.
- [x] Define an independent research question and distinguish automated routing from human outcomes.
- [x] Specify seven questions, independent labels and paired conditions.
- [x] Specify primary outcome, budgets, splits and optional extension.
- [x] Strengthen primary comparison to identical evidence with different organization; add held-out variants and checker baseline.
- [x] Prepare draft config, prompts, runbook and report outline.

## Before compute rental
- [x] Implement case generators and checkers; validate hand-computed and adversarial fixtures.
- [x] Validate every corruption and eliminate prompt/filename label leakage.
- [x] Assert U/S record equality and label-blind ordering; freeze variant holdouts.
- [x] Validate the separate deterministic-checker baseline and run illustrative precision simulations.
- [x] Implement scorer, append-only records, resume and CPU analysis.
- [x] Test token likelihood boundaries and chat template behavior.
- [x] Resolve model revisions; install/test the locked CPU environment. CUDA-host setup awaits the smoke run.
- [ ] Confirm provider, price, spend ceiling, storage and automatic shutdown.

## Before held-out runs
- [ ] Complete smoke test and measured cost forecast.
- [ ] Review development labels and failure cases.
- [ ] Record user's predictions and decisions in their own words.
- [ ] Freeze protocol/config/prompts/code/case splits and environment hashes.

## Before claiming completion
- [ ] Complete held-out inference or explicitly report incomplete cells.
- [ ] Independently label natural outputs; report all unassessable records.
- [ ] Analyze natural and controlled arms separately with paired uncertainty.
- [ ] Report new-instance/held-out-variant strata and prevalence sensitivity without tuning on test results.
- [ ] Check random/oracle baselines, denominators and artifact traceability.
- [ ] Write findings including negative results and limitations.
- [ ] Reproduce at least one table and plot from exported raw records.
- [ ] Record actual hardware and compute cost; shut down rented instance.
- [ ] Prepare truthful resume wording from completed work only.

## Explain back before an interview
- [ ] Explain why a report about a failed workflow can itself be correct.
- [ ] Explain why review allocation is not actual human error detection.
- [ ] Calculate the oracle recall ceiling at 20% review and 50% error prevalence.
- [ ] Explain risk versus uncertainty and why confidence can fail.
- [ ] Explain why all variants share a split and bootstrap cluster.
- [ ] Explain what controlled errors establish and what natural errors add.
